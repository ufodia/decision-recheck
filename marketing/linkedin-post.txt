Your product changed. Is your advice still describing yesterday's offer?

A feature moves to a higher plan. The ad and support answer still promise the old one. A buyer's budget hasn't changed.

I built Decision Recheck to make those decisions reviewable—and to recheck them when the evidence changes.

The local runner uses four optional LLM roles:

01  Requirements researcher — selects planning priorities before task execution.
02  Offer and support analyst — prioritizes recorded comparisons and follow-ups.
03  Evidence reviewer — prioritizes decisions and evidence limits.
04  Report writer — arranges application-owned decision explanations.

The roles select allowed review items. The application renders the recorded decisions and required follow-ups from the current evidence.

That boundary matters:

• A recorded “fails” stays “fails.”
• Behavior must be verified before changing factual documentation.
• Invalid or incomplete model selections leave visible partial work.

Browser checks run deterministically; model narration does not replace recorded task results. Human review still matters.

I tested the four-role flow against HTTPX's public Introduction and QuickStart documentation with fresh OpenAI gpt-4.1-mini responses: four for the baseline and four for the recheck. The recheck reran a read-only browser task with three text assertions. The full local suite passed 335 tests on November 15, 2026.

That test examined documentation and browser text; it did not execute HTTPX's library behavior or test a support service. The accepted role selections met the review contract; they are not independent corroboration of the source.

The hosted demo is a fictional, key-free walkthrough. Real website checks and optional live model review run locally with your provider configuration.
